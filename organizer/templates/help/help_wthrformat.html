Step 1/3. Required Weather Format

Your weather data must be prepared in a plain text file and strictly follow the format or specification PySawit Web recognizes, failing which could cause erroneous file readings. Once the file is ready, you will then upload it into PySawit Web before use. PySawit Web requires the following weather parameters to be supplied in the weather file:

Table 1. Weather parameters required by PySawit Web.

Daily parameter Units Column header
day of year number of the day in the year between 1 (Jan. 1) and 365 (Dec. 31) doy
mean daily min. air temperature °C tmin
mean daily max. air temperature °C tmax
mean daily wind speed m s-1 wind
total daily rainfall mm day-1 rain

Finally, your weather data text file must not exceed 1 Mb. Weather files must be prepared in the following manner:

  1. Data cleanup. It is important your weather data be first checked so that they are continuous (that is, no gaps between readings or measurements) and complete (that is, no missing values). PySawit Web does not perform any interpolations to deal with discontinuous data or missing values. DO NOT enter special codes like "-999" for missing values. All missing values must be corrected by estimation or interpolation, for instance.

    You will also need to check (and correct) for any outliers in your weather data.

  2. Format for weather data file. An example of a correctly formatted weather data file is shown in Fig. 1.

    • Comment lines:  The first three lines, staring with the hash symbol #, are actually optional and can be deleted, as PySawit Web will ignore any lines starting with the hash symbol #. However, comments are useful for documentation purposes. You will want to provide some information to describe the weather data in the file, such as the site name, location, elevation, height of weather measurements, and start and end of the weather data. Comment lines, if present, must always begin from the top or start of the file.

    • Column headers:  The line immediately after the comment lines lists the column headers, where doy, tmin, tmax, wind, and rain denote the column data for day of year, minimum air temperature (°C), maximum air temperature (°C), wind speed (m s-1), and rain (mm), respectively. Note the asterisk * before doy which indicates that doy is the key, used by PySawit Web to retrieve the daily weather properties for a given day of year. PySawit Web requires all weather data files to prefix the doy field with an asterisk *.

    • Weather data:  The order of the column headers is important because the weather data will follow their sequence. In Fig. 1, the first column of the weather data (fifth line and onwards) is for day of year, the second for minimum air temperature, the third for maximum air temperature, the fourth for wind speed, and the last for rain, following the sequence of the column headers in line 4: doy, tmin, tmax, wind, and rain. Also notice that the weather data (line 5 and onwards) have values separated by commas.
  3. A recommended method to prepare your weather file is to use Excel to first clean and format your weather data. In this example, columns A, B, C, D, and E are for day of year, min. air temperature, max. air temperature, wind speed, and rain, respectively. Do not forget to prefix * to doy (cell A1).
  4. The sequence of the column headers does not have to follow that in Fig. 2 but can be changed. In Fig. 3, for instance, the column headers are instead specified in the sequence of max. air temperature, min. air temperature, wind speed, rain, and lastly, the day of year. So long as the weather data follow the sequence of the column headers, PySawit Web will be able to correctly identify your weather parameters.
  5. Similarly, you can have additional weather data (such as soil temperature and dew temperature) in your weather file. However, as stated earlier in Table 1, PySawit Web requires only min. and max. air temperature, wind speed, and rain, so the additional weather parameters will not be used. Although ignored, the additional weather data would still require unique column header names to be provided. Fig. 4 is an example where column A holds information on weather dates (dd-mm-yy), denoted by the column header date. However, the entire column of date data are ignored and not used in crop simulations.
  6. Period of weather data.  You do not actually have to match the length of weather data to that of a simulation run duration. For instance, a simulation run for 20 simulation years does not mean you require at least 20 years of weather data. At minimum, PySawit Web requires only one day of weather data. And if a simulation run length exceeds the time span of the provided weather data, the weather data will "loop back" (i.e., rewind) to the start of the weather data set, so that simulations can continue, uninterrupted.
  7. Day of year and leap years  To simplify weather file preparations, PySawit Web does not treat leap years any different than non-leap years. For PySawit Web, one year of weather data always starts with doy=1 (day of year=1) and ends with doy=365, even for leap years. Fig. 6 illustrates this point. Rows 2 to 366 mark one year of weather data for the year 1987 (from doy=1 to 365). The following year, 1988, is a leap year (rows 367 to 732), but for PySawit Web, the second year data set starts from row 367 (doy=1) and ends at row 731 (doy=365). Similarly, the third year weather data starts and ends at row 732 and 1096, respectively.
